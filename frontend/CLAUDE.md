## Stack

Vite + React + TypeScript (strict), React Router (`createBrowserRouter`, library mode), TanStack Query, Tailwind CSS v4, shadcn/ui, react-hook-form + zod. No Next.js, no Redux or Zustand, no axios unless there's a reason. `SPEC.md` says why.

## Commands (run from `frontend/`)

- Install: `npm install`
- Dev server: `npm run dev` (http://localhost:5173). Needs the backend on port 8000: `uv run fastapi dev main.py` from `Backend/` with `docker compose up -d db`, or `docker compose up -d` for the whole backend.
- API types: `npm run gen:api` regenerates `src/types/api.d.ts` from `http://localhost:8000/openapi.json` (backend must be running). Run it after any backend schema change. Without a running backend, export the schema from the app (`json.dump(main.app.openapi(), ...)` with dummy `SECRET_KEY`, `S3_BUCKET_NAME`, `DATABASE_URL` set) and point `npx openapi-typescript <file> -o src/types/api.d.ts` at the file.
- Type check and lint: `npm run build` (runs `tsc -b` then `vite build`), `npm run lint` (oxlint, which the Vite template ships instead of ESLint). The existing warnings are in shadcn's generated `button.tsx`, `form.tsx` and `tabs.tsx`, and two in `ProtectedRoute.tsx` (a ref read during render).
- Tests: `npm test` (Vitest, `npm run test:watch` to watch). They cover logic without a browser: `lib/api-client.test.ts` (token, the 401 retry, error shapes, request bodies), `lib/format.test.ts` (period and countdown labels), `features/picks/schema.test.ts` (the pick form's rules and the save plan), `features/chat/state.test.ts` (the chat's merge rules), `features/chat/errors.test.ts` / `schemas.test.ts` and `features/auth/schemas.test.ts` (the form rules that mirror the backend's). Test files sit next to the code, are `*.test.ts`, run in node, and stub `fetch` and `localStorage`. There are no component tests.
- Add a shadcn component: `npx shadcn@latest add <name>`

## Where things live

- `src/main.tsx` mounts `QueryClientProvider`, `AuthProvider` and `RouterProvider`; `src/router.tsx` is the route table; `components/layout/AppShell.tsx` is the navbar plus `<Outlet />` and the toaster.
- `lib/api-client.ts`: `request()` and the `api.get/post/put/patch/delete/login/upload` helpers, `ApiError`, the token in `localStorage` (`getToken`/`setToken`/`clearToken`), and `setAuthResetHandler` for the `AuthProvider` to register on. `lib/query-client.ts` doesn't retry 4xx errors. `lib/format.ts` has the time and score helpers.
- Generated types are read as `components["schemas"]["GameResponse"]` from `@/types/api`. The `@` alias is set in `vite.config.ts` and both tsconfigs.
- Tooling: TypeScript is pinned to 5.9 because `openapi-typescript` crashes on TypeScript 7 (it needs the JS compiler API, which 7 no longer has). Don't bump it until `openapi-typescript` supports 7.
- Two deliberate edits to shadcn's generated code: `lib/utils.ts` is the standard `clsx` + `tailwind-merge` `cn` (this shadcn version generated an import from an obscure `cn` npm package), and `ui/sonner.tsx` fixes `theme="dark"` instead of importing `next-themes`. `ui/select.tsx` opens below its trigger (`position` defaults to `popper`, and the popper viewport no longer has a fixed height): Radix's default `item-aligned` slid the list over whatever was above the trigger. Re-adding a component through the cli brings the `cn` import back and may ask to overwrite `button.tsx` (answer no): change the import to `@/lib/utils` and `npm uninstall cn` if it was reinstalled.
- Theme: `index.css` defines one dark palette on `:root` (no `.dark` class, no light mode). The logo red `#BD1B21` is `--primary` and `--ring`. Fonts are `@fontsource-variable/inter` (`font-sans`) and `@fontsource/barlow-condensed` (`font-display`).
- **Auth** (`features/auth/`): `AuthProvider` keeps the user in the query cache under `["me"]` (switched on by a stored token) and exposes `useAuth()` = `{user, isLoading, login, register, logout}`; the context lives in `auth-context.ts` and the hook in `useAuth.ts` so the provider file only exports a component. `login` stores the token, fetches `/me`, then invalidates every other query (`liked_by_me` and the like change with who's reading); `logout` clears the token and the whole query cache. `register` is the POST then `login`. A 401 that the api client recovers from calls the provider's reset handler, which drops the user and shows an "expired" toast. `schemas.ts` has the zod rules for the forms (they mirror `schemas.py`; the server stays the authority and its 409/400 messages are shown), `errors.ts` turns any error into text.
- `components/layout/ProtectedRoute.tsx` wraps `/settings`: waits for `/me`, sends a never-logged-in visitor to `/login` with `state.from`, and sends someone who had a user and lost it (logout, expiry) home. `/login` and `/register` redirect a logged-in visitor to `useReturnTo()` (the `from` state, or `/`). The navbar's account area is `UserMenu` (avatar, profile, settings, log out), empty while `isLoading`.
- `components/MediaCard.tsx` is the tile (link, optional image, dark overlay, hover cta); the home page uses them for the links under the next game.
- **Games** (`features/games/`): `api.ts` (`fetchGames`, `fetchGame`, `fetchAllGames`, which pages through the schedule because playoffs can pass the 100 limit), `keys.ts` (`gamesKey(filters)`, `allGamesKey`, `gameKey(id)`), `hooks.ts` (`useGame`, `useNextGame`, `useSeasonGames`). `useGame` and `useNextGame` refetch every 30s while the game is `live`, and while it is "starting" (`scheduled` with `picks_open` false: tipoff passed, poller not caught up), both read from the api's fields. Components: `StatusBadge`, `Countdown` (counts to `tipoff_utc` and, at zero, invalidates the game queries once so the server decides what happens next), `GameCard` (a schedule row), `GameHeader` (teams, score, clock or countdown, postponed banner), `BoxScore` (one table per team, a did-not-play row shows the nba's comment), `NextGame` (home hero). `GamesPage` has Upcoming (oldest first, includes postponed) and Finished (newest first) tabs; `GameDetailPage` handles a 404. `hooks/useNow.ts` is the ticking clock for countdowns.
- **Picks** (`features/picks/`): the form is built from `GET /api/pick-categories`, one string per category in a `PickValues` record keyed by category id (`schema.ts`: `toFormValues`, `buildPickSchema`, and `planSave`, which turns the form plus the saved picks into the ordered create/update/delete requests the backend's winner-first rules allow; it is pure and tested). `hooks.ts`: `useCategories`, `useRoster` (the followed team's players, `FOLLOWED_TEAM` in `lib/constants.ts`, which mirrors the backend's `team_tricode`: change both together), `useMyPicks`, `useGamePicks` (infinite query), `useSavePicks` (runs the plan one request at a time, stops at the first failure, refetches `picks/me` either way, and on a 409 invalidates the game so a lock at tipoff shows). `GamePicks` chooses what the game page shows from the api's flags: `picks_open` is the form (or a login prompt when logged out), anything else is `MyPicks` (read-only, "Pending" until `points_awarded` is set), and `RevealedPicks` (everyone's picks, grouped by user, "Show more") is mounted only when `!picks_open` and not postponed, since before that the api answers 403. `PickForm` seeds from the saved picks with react-hook-form's `values` + `keepDirtyValues`, so a background refetch never overwrites typing. Picks refetch every 30s while a game is live or final-but-unscored.
- **Chat** (`features/chat/`): the whole room of a game is one `ChatState` in the query cache under `["chat", gameId]`, changed only through the pure functions in `state.ts` (`mergeNewest`, `appendNew`, `prependOlder`, `upsert`, `remove`; tested, since the merging is the easy part to get wrong). `useGameChat(gameId)` keeps it current three ways: the query's own `queryFn` fetches the newest page every 30s and *merges* it into the cached state (edits, likes and deletes of recent messages arrive this way, and messages scrolled back to are kept); an effect polls `?after=<newest id>` every 3s only while `roomOpen` and the tab is visible, catching up page by page, and again when the tab comes back to the front; `loadOlder` fetches `?before=<oldest id>` (a "Load earlier messages" button, not scroll-triggered). `useChatActions(gameId)` has the mutations (send, edit, like/unlike, delete as author or admin, mute); each applies the api's response to the cached state, and a 404/409 refetches the page. Components: `ChatRoom` (panel, closed/login/composer footer; before `opens_at` it says when it opens, otherwise "Chat closed", and openness itself is the api's `roomOpen`), `MessageList` (follows new messages only when already at the bottom, keeps position when older ones are added above, a "New messages" pill otherwise), `MessageItem` (like, and a menu: Edit while `now < editable_until`, Delete, and for admins Delete and Mute author), `MessageComposer` (Enter sends, Shift+Enter newline, 500 character counter, the server's error shown under the box), `MuteDialog`, `ConfirmDialog`. `chatErrorMessage` rewrites the api's "muted until <iso>" into the reader's local time. `MESSAGE_MAX_LENGTH` in `lib/constants.ts` mirrors the backend's 500.

## Conventions

- **Relative API urls only** (`/api/...`, `/static/...`). Vite's dev proxy and nginx forward them to FastAPI, so the app is same-origin everywhere: no `VITE_API_URL`, no CORS.
- **Types come from the backend.** Use the generated types in `src/types/api.d.ts`; never hand-write a type for an API response and never edit that file.
- **Never re-derive what the API decides**: `picks_open`, `room_open`, `opens_at`, `closes_at`, `editable_until`. Read them; still handle the 409 when a window closes mid-action.
- **All requests go through `lib/api-client.ts`**: it adds the token, turns FastAPI's `{"detail": ...}` into one `ApiError`, and on a 401 clears the token and retries once without it (public endpoints still 401 a stale token).
- **Server data lives in TanStack Query**, not in component state or context. Context holds auth only. Query keys are defined once per feature (see `SPEC.md`).
- **Features mirror the backend routers** (`features/games`, `features/picks`, `features/chat`, ...): each has `api.ts` (plain request functions), hooks, and its components. Pages in `pages/` stay thin and compose features.
- `components/ui/` is shadcn's generated code: change it through the shadcn cli where possible, and build project components on top of it in `features/*/components`.
- **Desktop-first.** Write desktop styles unprefixed and adjust smaller screens with `max-lg:` / `max-md:`.
- Times: the API sends UTC; display with `Intl.DateTimeFormat` in the browser's time zone (helpers in `lib/format.ts`).
- Login is form-encoded (`URLSearchParams`), with the email in the `username` field. Everything else is JSON, except the avatar upload (multipart).
- The routes `/games/:gameId` and `/reset-password?token=` are linked from the backend's emails: don't rename them.
- The Raptors claw logo (`public/raptors-logo.svg`) is used in the navbar and as the favicon. No NBA logos, opponent logos or player photos: teams appear as text.
- Look and feel is after insider.raptors.com (see `SPEC.md`): dark only, no hover pills on nav links, `MediaCard` for tiles, `font-display` (Barlow Condensed) for big uppercase titles.
- Comments follow the backend's style: lowercase, say why rather than what, at the end of the line or just above.
